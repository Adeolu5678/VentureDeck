# Part VI: External Interfaces and Dependencies

## 6.1. Backend & Database

### Convex
- **Role:** Core backend-as-a-service platform.
- **Capabilities:**
  - Real-time database with reactive subscriptions
  - Serverless function execution (queries, mutations, actions)
  - Scheduled function execution (cron-like jobs)
  - Internal mutations for background processing
  - HTTP actions for webhook handling
  - File storage with access control
- **SDK:** `convex` (NPM package)
- **Pricing:** Usage-based (free tier available)
- **Documentation:** [docs.convex.dev](https://docs.convex.dev)

---

## 6.2. Authentication

### Clerk
- **Role:** Identity and access management.
- **Capabilities:**
  - Email/password authentication
  - Social login (Google, GitHub, etc.)
  - Session management with JWT
  - User metadata storage
  - Webhooks for user lifecycle events
- **Integration Points:**
  - Frontend: `@clerk/nextjs` for React components and hooks
  - Backend: JWT validation in Convex functions
  - Webhooks: User created/updated/deleted events
- **Configuration:** 
  - Publishable Key (client)
  - Secret Key (server)
  - JWT Issuer Domain (Convex)
  - Webhook Secret (Convex)
- **Documentation:** [clerk.com/docs](https://clerk.com/docs)

## 6.11. Interface Contracts

### Clerk Webhooks

**Endpoint:** `POST /api/webhooks/clerk` (or Convex HTTP action)

**Events Handled:**
- `user.created` - Create user record in Convex
- `user.updated` - Sync profile changes
- `user.deleted` - Handle user deletion

**Verification:** SVIX signature validation

### Convex HTTP Actions

**Webhook Handler Location:** `Convex/convex/webhooks.ts`

**Responsibilities:**
- Validate incoming webhook signatures
- Parse event payloads
- Execute appropriate mutations
- Return success/error responses
