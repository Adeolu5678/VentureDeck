# Part II: System Architecture and Design

## 2.1. Architectural Blueprint (The Modern Web Stack)

VentureDeck is a serverless web application leveraging the power of Convex and Next.js to provide a seamless, real-time experience for Entrepreneurs and Investors. The architecture is designed for speed, scalability, and real-time interactivity.

### Core Technology Stack

| Layer | Service / Technology | Role in VentureDeck |
| :--- | :--- | :--- |
| **Identity & Auth** | Clerk | Handles dual-role authentication (Entrepreneur/Investor), session management, webhooks, and identity verification. |
| **State & Logic** | Convex | Real-time database and backend functions. Manages projects, applications, deal flows, and all business logic. |
| **Data Storage** | Convex File Storage | Stores pitch decks, legal documents, data room files, logos, and user avatars securely. |
| **Real-time Updates** | Convex Subscriptions | Pushes live updates for new applications, messages, project status changes, and activity feeds. |
| **Scheduled Jobs** | Convex Scheduler | Runs daily analytics snapshots and traction score recalculations. |
| **Frontend (Web)** | Next.js 15 (React) | The responsive user interface with App Router, featuring distinct dashboards for different user roles. |
| **Frontend (Mobile)** | Flutter | Cross-platform mobile app (iOS/Android) currently in development. |
| **Styling** | Tailwind CSS + Custom Design System | Premium design with glassmorphism, animations via Framer Motion. |
| **Typography** | Google Fonts | Sora (headings) and Outfit (body) for professional, modern look. |

## 2.3. Data Strategy

This data model is optimized for high-integrity structured data (financials, project specs) and real-time communication.

### Database (Convex)

The database contains 22 tables organized into functional categories:

#### Core Entity Tables
- **`users`**: Platform users with roles, profiles, and settings.
- **`projects`**: Startup projects with pitch information and metrics.
- **`workspaces`**: Team collaboration spaces linked to projects.

#### Communication Tables
- **`conversations`**: Chat channels (direct, workspace, interview, custom).
- **`messages`**: Individual chat messages with optional attachments.
- **`notifications`**: Platform notifications for all user events.

#### Application & Team Tables
- **`applications`**: Job/team applications with status workflow.
- **`applicationTemplates`**: Reusable application message templates.

#### Traction & Engagement Tables
- **`milestones`**: Project milestone tracking with verification.
- **`bounties`**: Micro-task postings with full workflow.
- **`soft_circles`**: Investor commitment tracking.
- **`project_followers`**: Investor project following relationships.
- **`vouches`**: User-to-user reputation endorsements.

#### Analytics Tables
- **`projectAnalytics`**: Daily metric snapshots for projects.
- **`projectViews`**: Real-time view tracking data.

#### Due Diligence Tables
- **`dataRooms`**: Secure document rooms for projects.
- **`dataRoomDocuments`**: Files within data rooms.
- **`dataRoomAccess`**: Access control and audit trail.

#### Legal & Compliance Tables
- **`legalDocs`**: Generated legal documents for projects.
- **`certifications`**: User professional certifications.

#### Social Tables
- **`friends`**: User-to-user friend connections.

#### Platform Configuration Tables
- **`featureFlags`**: Admin-controlled feature toggles.
- **`savedSearches`**: Investor saved search filters.

### File Storage (Convex)

| Content Type | Purpose | Access Control |
| :--- | :--- | :--- |
| **Project Logos** | Brand identity for project cards | Public read |
| **Pitch Decks** | PDF pitch presentations | Project members + authorized viewers |
| **Data Room Documents** | Confidential due diligence files | Explicit grant only |
| **Legal Documents** | Generated agreements | Project owner + signers |
| **User Avatars** | Profile pictures | Public read |
| **Certification Images** | Proof of credentials | User + admins |

## 2.4. Real-time Architecture

VentureDeck leverages Convex's real-time capabilities extensively:

### Reactive Subscriptions
- **Message streams**: New messages appear instantly in all chat views.
- **Application updates**: Status changes push to both applicant and founder.
- **Project changes**: Edits reflect immediately across all viewers.
- **Notification feed**: New notifications appear without refresh.
- **Activity feeds**: Personal and discover feeds update in real-time.

### Optimistic Updates
The UI uses optimistic updates for instant feedback:
- Sending messages shows immediately before server confirmation.
- Following/unfollowing projects updates UI without waiting.
- Application submissions show pending state immediately.

## 2.5. Security Architecture

### Authentication Flow
1. User authenticates via Clerk (email, social, or passwordless).
2. Clerk issues JWT with user claims including `clerkId`.
3. Each Convex function validates JWT and extracts user identity.
4. User record is retrieved via `by_clerk_id` index for authorization.

### Authorization Model
- **Role-based**: Entrepreneurs vs Investors have different capabilities.
- **Resource-based**: Project ownership determines edit/delete permissions.
- **Member-based**: Workspace membership grants access to team features.
- **Admin override**: `isAdmin` flag grants moderation capabilities.

### Data Protection
- All data in transit encrypted via TLS.
- Convex Row-Level Security enforces data isolation.
- Data Room access requires explicit grants.
- Audit trails track document access.
